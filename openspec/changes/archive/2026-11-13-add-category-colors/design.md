## Context

見 [proposal.md](proposal.md) 的動機。現有 `Category` 只有 ID、名稱與時間；`validateCategory` 同時供 repository、完整備份與還原使用。一般分類的「⋯」選單目前只提供重新命名與刪除，重新命名表單在原分類位置顯示。側欄以 CSS semantic tokens 支援明暗模式，最小寬度為 240px。

## Goals / Non-Goals

**Goals:**

- 不改變既有分類及舊備份的預設外觀或可讀取性。
- 名稱與顏色以單次 repository command 保存，避免部分成功。
- 在窄側欄仍可操作色盤、HEX 欄位與預覽。

**Non-Goals:**

- 不替使用者檢查或修正顏色對比。
- 不更改群組卡片外的搜尋結果、置頂區或右鍵選單的顏色。
- 不加入外部選色套件或雲端同步。

## Decisions

1. **資料採可選的 `backgroundColor`／`textColor` 欄位，格式為標準化 `#RRGGBB`。** 未設定時兩欄皆不存在；既有 v3 分類、完整備份可直接通過新版驗證，不需為可選欄位提高 storage schema version。替代方案是新增獨立 UI preference，但會讓備份與分類刪除／復原需要額外同步兩份資料。
2. **新增單一分類更新 command。** repository 在同一 revision 下驗證名稱和顏色，寫入完整 Category，並保留 ID、建立時間、Bookmark 與順序；「未分類」沿用不可編輯保護。替代方案是依序呼叫 rename、setColor，可能造成一半儲存成功。
3. **編輯表單保留草稿，儲存前只更新表單內預覽。** 背景色提供常用色按鈕與原生選色器，兩種顏色各有可直接輸入的 HEX 欄位；預覽同時呈現分類標題、書籤標題與筆記。無效色碼顯示欄位錯誤並阻止儲存。恢復預設會把兩種草稿色一起清空；按儲存後才清除持久化欄位。替代方案是選色即寫入，與取消不生效的需求衝突。
4. **已儲存顏色作用於整張分類卡片。** 將背景與前景 CSS 變數設在 CategorySection，讓標題、數量、箭頭、拖曳把手、書籤標題、筆記、時間與操作圖示使用同一組顏色；未設定則完全沿用既有 token。選單與輸入欄位仍使用語意 token，保持表單可辨識。拖曳落點仍以邊框／外框提示，避免蓋掉自訂背景色。自訂色在明暗模式不轉換；搜尋結果與置頂區不屬於分類卡片，因此不套用分類顏色。
5. **完整備份沿用現有格式版本。** 備份序列化 Category 自然包含新欄位；還原仍透過 `validateLibraryData`，因此舊備份因欄位可選而有效，顏色不會繞過驗證。分類刪除／復原使用既有完整 Category snapshot，會一併保留顏色。

## Risks / Trade-offs

- [使用者選到難讀的配色] → 編輯時提供含書籤列的整張卡片預覽；依已確認需求不阻止儲存。
- [手動輸入暫時不是完整 HEX] → 色碼輸入保留草稿，只有完整有效時更新選色器與預覽；儲存時顯示錯誤。
- [窄側欄的編輯表單過寬] → 色盤與兩個色碼欄位使用可換行布局，並在 240px 寬度驗證。

## Migration Plan

新增可選欄位後直接讀取既有 v3 資料；不批次改寫現有 Category。舊版備份不含色彩欄位時還原預設外觀。回退舊程式時，舊 validator 會忽略額外欄位並保留原始 Category record；再次升級後顏色仍可讀取。
